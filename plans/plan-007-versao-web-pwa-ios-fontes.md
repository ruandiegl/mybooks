# TrocaLivros PWA para iPhone — fontes primárias (28/09/2026)

Este levantamento apoia o plano de implementação da versão web do app atual. As recomendações marcadas como **inferência** aplicam as fontes ao repositório; não equivalem a um teste de funcionamento no iPhone. Documentação de Expo e React Navigation consultada também via Context7 (`/websites/expo_dev` e `/websites/reactnavigation`).

## Reaproveitar o app Expo

- O Expo documenta `react-native-web` para compartilhar componentes `View`/`Text` e lógica entre nativo e web; recomenda essa opção para maximizar reaproveitamento. A produção web é gerada com `npx expo export --platform web` em `dist/`. [Expo: desenvolver para web](https://docs.expo.dev/workflow/web/), [Expo: publicar websites](https://docs.expo.dev/guides/publishing-websites/).
- **Inferência:** usar o mesmo projeto `app/` (Expo SDK 57, React Navigation e React Native Web já presentes) é o caminho de menor divergência funcional e visual. Fazer componentes específicos `.web.tsx` apenas onde uma API ou interação nativa impedir a paridade; não é necessário migrar para Expo Router só para ter PWA. O guia do Expo de PWA distingue a página HTML de apps `web.output: "single"` da renderização `static`/`server` baseada em Expo Router. [Expo: PWA](https://docs.expo.dev/guides/progressive-web-apps/), [Expo: web](https://docs.expo.dev/workflow/web/).
- A documentação atual do Expo manda instalar `react-dom`, `react-native-web` e `@expo/metro-runtime` para desenvolver para web; conferir compatibilidade da instalação existente antes de exportar. [Expo: web](https://docs.expo.dev/workflow/web/).

## Instalação e publicação no iPhone

- O Expo orienta criar `public/manifest.json` com nome, ícones, `start_url`, `display: "standalone"`, cores, e vinculá-lo em `public/index.html` para saída `single`. Ícones de 192 e 512 px são o exemplo documentado. [Expo: PWA](https://docs.expo.dev/guides/progressive-web-apps/).
- A Apple explica que um manifesto com `display: standalone` ou `fullscreen` faz o site instalado abrir como web app separada do Safari. Para orientar a banca, a Apple documenta abrir o endereço no Safari, usar Compartilhar → Adicionar à Tela de Início e ativar “Abrir como App Web” quando a opção aparecer. [WebKit: web apps na tela inicial](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/), [Apple: adicionar site à tela inicial](https://support.apple.com/en-ca/guide/iphone/iph42ab2f3a7/27/ios/27).
- **Inferência:** a entrega iOS da banca pode ser uma URL HTTPS e instruções de instalação, sem empacotamento ou submissão à App Store. A experiência em aba Safari e instalada deve ser verificada separadamente em um iPhone físico. [Apple: adicionar site à tela inicial](https://support.apple.com/en-ca/guide/iphone/iph42ab2f3a7/27/ios/27), [WebKit: web apps na tela inicial](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/).
- O Expo alerta que service workers mal configurados podem servir versões antigas por longo tempo. **Inferência:** para o primeiro marco, priorizar instalação, shell e modo de erro quando offline; acrescentar cache offline apenas com política pequena, versionada e testada. Nunca precachear respostas de autenticação, mensagens ou dados privados. [Expo: PWA, seção Service workers](https://docs.expo.dev/guides/progressive-web-apps/), [OWASP: sessão e cache](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).

## Navegação e aparência

- React Navigation oferece suporte web, mas pede `linking` para URLs por tela e uso de links/controles que emitam âncoras; stacks nativas não têm animações nem gestos nativos no navegador. Sua documentação descreve `web.output: single` como SPA que precisa de fallback de rotas para `index.html`. [React Navigation: web](https://reactnavigation.org/docs/web-support/).
- **Inferência:** manter o mapa de telas e a identidade visual do app, usar URLs reais para detalhes/chat/perfil e ajustar o botão voltar/histórico. A animação e o gesto de fechar o bottom sheet Premium precisam de implementação web própria se a atual depender de gesto nativo. Comparar em iPhone físico tamanhos, safe areas, teclado e rolagem. [React Navigation: comportamento web](https://reactnavigation.org/docs/web-support/).
- O Expo documenta publicação estática em Netlify e Vercel; para `single` mostra regra de rewrite para `index.html`. **Inferência:** qualquer hospedagem HTTPS que sirva `dist/` e tenha fallback SPA pode ser escolhida; a escolha não exige migrar a API do Railway. [Expo: publicar websites](https://docs.expo.dev/guides/publishing-websites/).

## Câmera, imagens e segurança do navegador

- `CameraView.onBarcodeScanned` e `useCameraPermissions` são listados para web, incluindo tipos EAN/UPC úteis a ISBN. Isso confirma suporte documentado, mas não prova compatibilidade com o fluxo atual em Safari; é necessário teste em dispositivo. [Expo Camera](https://docs.expo.dev/versions/latest/sdk/camera/).
- `expo-image-picker` documenta `launchCameraAsync` e `launchImageLibraryAsync` para web; a abertura deve ocorrer diretamente após toque do usuário. Os métodos de permissão da biblioteca não solicitam as mesmas permissões no navegador. [Expo ImagePicker](https://docs.expo.dev/versions/latest/sdk/imagepicker/).
- Câmera via navegador requer contexto seguro (HTTPS, exceto localhost) e autorização do usuário. O Expo também destaca que seu servidor local HTTP não reproduz todos esses recursos. **Inferência:** validar leitura ISBN, foto de capa e avatar na URL HTTPS final, no Safari e no app instalado; prever entrada manual de ISBN se a câmera falhar ou for negada. [MDN: getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia), [Expo: publicar e servir localmente](https://docs.expo.dev/guides/publishing-websites/).

## Sessão, API Railway e tempo real

- `expo-secure-store` é documentado para Android/iOS/tvOS, sem web. O exemplo oficial de autenticação Expo usa `localStorage` como fallback para navegador, porém a OWASP recomenda não guardar tokens de autenticação nem refresh tokens em `localStorage`/`sessionStorage` por exposição a JavaScript e XSS. [Expo SecureStore](https://docs.expo.dev/versions/latest/sdk/securestore/), [Expo: exemplo de persistência por plataforma](https://docs.expo.dev/router/advanced/authentication/), [OWASP: gerenciamento de sessão](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).
- **Inferência:** o `authStorage.ts` atual precisa de implementação `.web.ts` e de uma decisão explícita de sessão web. A opção mais robusta é refresh/sessão por cookie `HttpOnly; Secure; SameSite`, com acesso curto em memória e proteção CSRF correspondente. Se o frontend e a API ficarem em domínios de sites diferentes, testar bloqueio de cookies no Safari; preferir mesmo site (`app.`/`api.` no mesmo domínio registrável) ou proxy de API no mesmo origin. [OWASP: cookies de sessão](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html), [WebKit: bloqueio de cookies de terceiros](https://webkit.org/blog/10218/full-third-party-cookie-blocking-and-more/).
- O Web Locks API mantém uma rotação de refresh por vez entre abas e workers do mesmo origin. WebKit a incluiu em Safari 15.4; **inferência:** exigir esse mínimo na PWA evita que refresh token rotativo chegue simultaneamente com o mesmo valor e seja identificado como replay. [WebKit: novos recursos do Safari 15.4](https://webkit.org/blog/12445/new-webkit-features-in-safari-15-4/).
- Variáveis `EXPO_PUBLIC_` são embutidas em texto legível no bundle. **Inferência:** apontar `EXPO_PUBLIC_API_BASE_URL` e `EXPO_PUBLIC_SOCKET_URL` do build web para a URL HTTPS pública do Railway; jamais colocar chave, token ou segredo nesses valores. Validar o `dist/` publicado, porque mudar variáveis exige novo build. [Expo: variáveis de ambiente](https://docs.expo.dev/guides/environment-variables/).
- O navegador aplica CORS à API entre origens diferentes. Socket.IO exige `cors.origin` explícito para polling; WebSocket não é restringido por CORS, então autorização do socket continua necessária. **Inferência:** permitir apenas a origem HTTPS do PWA nas configurações da API Railway e testar REST, preflight e chat. [Socket.IO: CORS](https://socket.io/docs/v4/handling-cors/).
- **Inferência:** imagens antigas que ainda apontam para endereço privado `192.168.x.x` não serão carregadas por iPhone externo e, em página HTTPS, conteúdo HTTP misto também é problemático. Migrar URLs armazenadas para mídia pública HTTPS ou resolver via identificador estável da API. [OWASP: sessão TLS e conteúdo misto](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).

## Prioridade e limites para o MVP de banca

**Decisão arquitetural após revisão do plano:** criar `web/` para build e hospedagem da PWA, mantendo `app/` como fonte das telas compartilhadas. Publicar `web` e `API` como serviços distintos no mesmo ambiente Railway; `web` encaminha rotas HTTP e Socket.IO pela rede privada, de modo que o Safari use um único origin e a API permaneça disponível ao APK. A documentação do Expo confirma o reaproveitamento de React Native Web e alerta que monorepos com múltiplos apps/pacotes têm custo de configuração; por isso esta decisão evita um segundo frontend e a migração completa para workspaces. **Inferência arquitetural**, a validar em deploy: [Expo: monorepos](https://docs.expo.dev/guides/monorepos/), [Railway: rede privada](https://docs.railway.com/networking/private-networking), [Caddy: reverse proxy e WebSocket](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy), [Railway: Dockerfiles](https://docs.railway.com/builds/dockerfiles).

1. Publicar uma versão web do mesmo código, com as telas e regras da API existentes, em HTTPS; instalar no iPhone e comparar fluxos com o APK Android. [Expo: web](https://docs.expo.dev/workflow/web/), [Apple: tela inicial](https://support.apple.com/en-ca/guide/iphone/iph42ab2f3a7/27/ios/27).
2. Tratar sessão web, CORS, rota direta, câmera, seleção de imagem, socket e URLs de mídia como critérios de paridade, não como detalhes cosméticos. Fontes: [Expo PWA](https://docs.expo.dev/guides/progressive-web-apps/), [React Navigation web](https://reactnavigation.org/docs/web-support/), [Expo Camera](https://docs.expo.dev/versions/latest/sdk/camera/), [Socket.IO CORS](https://socket.io/docs/v4/handling-cors/).
3. Push web e offline de dados privados não são necessários para simular a versão atual se o app não os oferece. WebKit suporta Web Push para web apps na tela inicial a partir do iOS 16.4, com permissão iniciada por gesto; considerar somente em fase posterior caso haja requisito de notificação. [WebKit: Web Push em iOS](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/).
